# 当前需求与验收标准

状态：用户需求已合并，本文为当前有效规格。更新日期：2026-10-20。
本文描述当前行为与验收要求，实现及各层验证状态见 [验证记录](validation.md)。

## 使用场景

- 中国大陆家庭宽带；部署目标为支持 Docker 的 NAS，包含 amd64／arm64。
- 家中现有 DNS 为路由器默认服务，没有 AdGuard Home 等专门 DNS 服务。
- 首批接入设备为 PlayStation、Xbox、Nintendo Switch。
- 首先让游戏主机直接查询 NAS DNS；路由器保持现有配置。NAS 使用固定局域网地址。
- 优化游戏下载与更新的可用性、速度及稳定性。对战网络、NAT 和跨区网络连接不属于首版验收目标。

## 自动选优行为

1. 启动即提供普通 DNS 转发，同时自动加载未过期策略和启动后台探测，无须用户点击测速。
2. 有已验证策略的目标域名立即使用策略；没有结果时先正常解析，并将目标加入去重、有界的后台任务队列。
3. 候选来自目标域名的上游解析、经验证的节点来源及历史结果。平台／域名／地址族分别验证，不默认共享节点可用性。
4. 节点必须先通过目标域名与下载样本兼容检查，再比较吞吐、成功率和稳定性；连接延迟仅用于初筛。
5. 后台在运行期间持续执行轻量健康检查、周期吞吐复测及异常后的重测。通过配置间隔与预算控制测试频率。
6. 新节点达到持续优势后自动应用；当前节点确认失效时切换至有效备用，无合格节点则停止覆盖并使用普通上游解析。
7. 选优只更新后续 DNS 应答；不承诺改变现有下载连接，也不承诺对有限候选以外的全部互联网节点获得全局最优。
8. 吞吐测试串行、连接初筛有界；可配置测试时间、流量预算、间隔及冷却时间。预算不足时继续低流量检查并显示吞吐结果的新鲜度。
9. DNS 查询不等待现场测速、数据库写入或 Web 服务处理；队列满或探测失败不阻塞普通解析。

## DNS 与兼容性

- 提供 UDP／TCP 53，处理 IPv4 A 和 IPv6 AAAA，尊重 CNAME 链、TTL、否定应答和 EDNS。
- 对目标域名执行精确规则，登录、支付和联机服务按普通解析处理；新增观察到的域名不自动升级为全平台通配规则。
- IPv4／IPv6 独立验证；默认保留普通 IPv6 语义，兼容选项仅作用于明确的目标规则。
- 改写结果属于本地策略，不声称具有上游 DNSSEC 验证结果。要求端到端签名验证的场景走原始上游应答。
- HTTPS／SVCB 地址提示可能影响客户端选址，必须验证其与策略的一致性；未覆盖的场景明确呈现适用范围。
- Xbox 国际／国内节点分组验证；HTTP 下载跳转作为独立可选模块，首版核心不依赖该模块。HTTPS 保持正常证书验证。
- 上游解析具备超时、重试与备用解析器，防止配置为自身造成循环。
- DNS 与管理入口仅允许配置的局域网／本地来源；管理界面无需登录，打开即可使用。管理写操作校验来源和自定义请求头，服务间接口使用独立密钥。

## NAS 与持久化

- 一个 Compose 项目运行 DNS 核心、控制与管理两个容器。产品独立部署，不要求用户安装 AdGuard Home；DNS 引擎库按协议正确性与维护成本选择，具体供应方不是业务需求。
- DNS 核心保存独立有效策略快照。管理容器故障时在策略有效期内继续解析，过期策略恢复普通上游。
- 安装检查宿主机端口、目录权限、数据卷文件系统和 IPv6 可达性；端口冲突给出具体处理路径。
- SQLite 数据在 NAS 本地数据卷，DNS 核心不直接打开该库；容器重建后恢复配置、历史与有效策略。
- 宿主机离线不属于单实例内部回退可解决的故障，部署说明提供恢复主机自动 DNS 的步骤。

## 管理界面

- 使用 React 构建中文管理界面，适配手机，提供总览、平台选优、接入检查、历史、设置。
- 采用 shadcn/ui 的 neutral 视觉风格：黑白灰语义色、细边框、紧凑控件、清晰层级与 Lucide 图标；状态同时使用文字，保留键盘焦点及手机可用性。
- 首页提供主机接入配置与指引：显示部署声明的 DNS 地址和标准端口、复制地址、PS5／PS4／Xbox／Switch 设置路径、备用 DNS 取舍、验证接入及恢复自动 DNS 的方法。未配置有效地址时不猜测浏览器域名或容器地址。
- 页面切换、主机指引切换、操作反馈及后台检测状态使用轻量动画；自动状态刷新不重复触发入场，系统减少动态效果偏好下停用非必要动画。
- 服务连接状态、自动选优状态及暂停／恢复操作统一位于左下角状态区，页面顶部不重复展示。状态区参与应用布局，导航和正文分别滚动；短窗口、手机及安全区域下都不能被裁切或覆盖，正文也不能被状态区挡住。
- 平台选优使用“全部／Xbox／PlayStation／Switch”Tab，表格内以地址族列同时展示 IPv4／IPv6 当前节点、速度和任务状态；支持一键测速当前平台或全部平台、逐域名测速及展开详情。批量测速按域名去重，复用有界队列、串行探测与流量预算。
- 平台下载规则使用列表维护，展开单条规则编辑样本和候选，支持新增、启停、移除和整体保存，保留高级 JSON 编辑。
- 接入检查直接提供 DNS 应答检查与最近查询的来源、域名和时间，无需登记主机。移除手动主机登记、接入状态推断及对应接口；首页保留主机 DNS 配置指引。
- 展示当前节点、备用、探测速度／成功率、结果时间、策略生效版本、切换原因与后台任务状态。
- 自动选优为默认状态，手动测速、固定节点和暂停选优为辅助操作。
- 明确区分服务端探测速度与主机实际下载速度；单靠 DNS 无法观测下载流量、游戏进度或即时带宽占用。
- 接入验证依据真实收到的查询及应答；经过路由器转发时，设备身份可能只能归到路由器，不推断不存在的设备明细。

## 验收标准

| 层级 | 必须提供的证据 |
| --- | --- |
| 软件 | 无人工点击即可完成候选探测、选择、发布和失效回退；首次查询不等测速；缓存与策略更新不冲突 |
| DNS 协议 | UDP／TCP、A／AAAA、CNAME、NXDOMAIN／NODATA、EDNS 截断与 TCP 重试、改写标志及 IPv6 策略验证 |
| 故障恢复 | 停止管理容器、损坏策略输入、探测超时、数据库不可写、节点失效、预算耗尽时解析行为符合规格 |
| Docker | 两种目标架构分别构建，容器启动、重建、数据恢复及端口绑定有记录 |
| NAS | 在明确记录的品牌／型号／系统／网络模式下验证主机查询可达、IPv6、源地址和重启恢复 |
| 真实主机 | 三平台分别对同一内容做多轮默认 DNS／选优 DNS 对比，记录时段、下载完成时间、平均速度与失败次数 |

软件测试、镜像构建、NAS 部署、主机实测分别报告；不使用某一层通过代替其他层验收。

## 源码发布

GitHub 仓库包含当前源码、依赖锁文件、通用 Docker 部署模板、需求与验证说明，以及第三方许可文本。本地密钥、数据库、查询记录、NAS 实际部署信息、构建缓存和工具不进入仓库。首次发布后核对远端提交与本地一致。

- GitHub Actions 在 main 推送、版本标签和手动触发时，先验证代码，再向 GHCR 发布同时包含 linux/amd64 与 linux/arm64 的镜像；PR 仅验证，不发布。
- main 使用 latest 与完整提交号标签，vX.Y.Z 使用版本及次版本标签；发布记录包含镜像摘要。NAS 默认拉取预构建镜像，Docker 自动选择架构；源码构建使用独立 Compose 覆盖文件，更新保留密钥和数据卷。
