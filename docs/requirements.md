# 当前需求与验收标准

状态：用户需求已合并，本文为当前有效规格。更新日期：2026-10-28。
本文描述当前行为与验收要求，实现及各层验证状态见 [验证记录](validation.md)。

NAS 平台暂不属于当前支持范围；以下部署要求针对通用 Docker 主机，现有 `NAS_IP` 配置名保持兼容。

## 使用场景

- 中国大陆家庭宽带；部署目标为支持 Docker 的服务主机，包含 amd64／arm64。
- 家中现有 DNS 为路由器默认服务，没有 AdGuard Home 等专门 DNS 服务。
- 首批接入设备为 PlayStation、Xbox、Nintendo Switch。
- 首先让游戏主机直接查询服务主机 DNS；路由器保持现有配置。服务主机使用固定局域网地址。
- 优化游戏下载与更新的可用性、速度及稳定性。对战网络、NAT 和跨区网络连接不属于首版验收目标。

## 自动选优行为

1. 启动提供默认 DNS；加载仍有效的公网 IPv4 优选与持久调度时间，无配置的首次启动自动测试启用规则，重启不重复启动刚完成的测试。
2. 候选来自配置表、手工候选、各上游的 A 应答及当前节点，按域名去重后全部测试。不能保证本机获得 CDN 的全部 IP，不共享其他域名的验证结论。
3. 吞吐测试串行，连接/响应头和下载窗口分别超时。默认下载窗口 5 秒，预热 min(500ms, 窗口的 1/5) 不计速度；短样本、错误内容、TLS 错误不得入选。没有限速、字节上限或每日预算，超时与取消始终有效。
4. 当前轮持续下载速度最高的合格节点优先；不按连接延迟筛掉候选，不让旧失败率或历史中位数覆盖当前测速。速度接近（默认小于 5% 优势）保持当前 IP；明显更快且经过默认 5 分钟冷却时单轮切换。
5. 默认完整复测间隔 24 小时、健康检查间隔 30 分钟。健康任务优先，并可在完整测试的候选之间执行；策略默认有效 2 小时，校验要求至少覆盖两个健康周期及 10 分钟余量。
6. 默认解析 → 完整测试后优选；正常复测期间使用旧优选。健康检查只验证当前 IP，失败立即撤销覆盖并发布默认解析，再完整复测，通过后重新优选，不直接激活旧备用。
7. 没有可用候选或全失败时使用默认解析，恢复测试采用 15、30、60、120、240 分钟退避；手动复测可立即排队，重复域名任务合并。手动恢复默认后等待定时测试或用户主动复测，旧任务不能覆盖此决定。
8. 后台填写 HTTPS 规则表 URL，默认 6 小时同步，可保存后立即同步。完整下载、校验后事务替换，失败保留上次可用配置；显示同步时间、版本和错误。公网 IPv4、证书、大小、超时、重定向边界均受检查。
9. DNS 查询不等待测速或数据库；有界异步观察队列满时丢弃记录而不阻塞解析。后台变化只影响客户端重新解析及建立的新连接。

## DNS 与兼容性

- 提供 IPv4 UDP／TCP 53，尊重普通域名的 CNAME、TTL、否定应答和 EDNS。
- 对目标域名执行精确规则，登录、支付和联机服务按普通解析处理；新增观察到的域名不自动升级为全平台通配规则。
- 仅优选公网 IPv4；启用下载规则的 AAAA 返回本地 NODATA，其他域名 AAAA 普通转发。移除 IPv6 候选、策略、接入地址与编辑入口。
- 改写结果属于本地策略，不声称具有上游 DNSSEC 验证结果。A 查询带 DO／CD 时走原始上游；目标 AAAA 的本地 NODATA 不声称通过上游 DNSSEC 验证。
- HTTPS／SVCB 地址提示可能影响客户端选址，必须验证其与策略的一致性；未覆盖的场景明确呈现适用范围。
- Xbox 国际／国内节点分组验证；HTTP 下载跳转作为独立可选模块，首版核心不依赖该模块。HTTPS 保持正常证书验证。
- 上游解析具备超时、重试与备用解析器，防止配置为自身造成循环。
- DNS 与管理入口仅允许配置的局域网／本地来源；管理界面无需登录，打开即可使用。管理写操作校验来源和自定义请求头，服务间接口使用独立密钥。

## 容器与持久化

- 一个 Compose 项目运行 DNS 核心、控制与管理两个容器。产品独立部署，不要求用户安装 AdGuard Home；DNS 引擎库按协议正确性与维护成本选择，具体供应方不是业务需求。
- DNS 核心保存独立有效策略快照。管理容器故障时在策略有效期内继续解析，过期策略恢复普通上游。
- 安装检查宿主机端口、目录权限、数据卷文件系统和 IPv4 可达性；端口冲突给出具体处理路径。
- SQLite 数据在服务主机本地数据卷，DNS 核心不直接打开该库；容器重建后恢复配置、历史与有效策略。
- 宿主机离线不属于单实例内部回退可解决的故障，部署说明提供恢复主机自动 DNS 的步骤。

## 管理界面

- 使用 React 构建中文管理界面，适配手机，提供总览、平台选优、接入检查、历史、设置。
- 采用 shadcn/ui 的 neutral 视觉风格：黑白灰语义色、细边框、紧凑控件、清晰层级与 Lucide 图标；状态同时使用文字，保留键盘焦点及手机可用性。
- 首页提供主机接入配置与指引：显示部署声明的 DNS 地址和标准端口、复制地址、PS5／PS4／Xbox／Switch 设置路径、备用 DNS 取舍、验证接入及恢复自动 DNS 的方法。未配置有效地址时不猜测浏览器域名或容器地址。
- 页面切换、主机指引切换、操作反馈及后台检测状态使用轻量动画；自动状态刷新不重复触发入场，系统减少动态效果偏好下停用非必要动画。
- 服务连接状态、自动选优状态及暂停／恢复操作统一位于左下角状态区，页面顶部不重复展示。状态区参与应用布局，导航和正文分别滚动；短窗口、手机及安全区域下都不能被裁切或覆盖，正文也不能被状态区挡住。
- 平台选优使用“全部／Xbox／PlayStation／Switch”Tab，展示默认／优选、公网 IPv4、速度、最近复测、下次计划和原因。主要操作为立即复测、恢复默认；固定节点收进高级操作，启用前仍需验证。没有预算或双地址族控件。
- 平台下载规则默认仅编辑平台、测试下载地址与启用状态；域名从下载地址提取，规则 ID 自动生成。候选 IP、内容校验和完整 JSON 放在高级选项，已有高级配置在普通编辑后保留。设置保存操作固定在内容区域右下角，滚动时可见，手机与短窗口下不得遮挡正文或左下角服务状态。
- 接入检查直接提供 DNS 应答检查与最近查询的来源、域名和时间，无需登记主机。移除手动主机登记、接入状态推断及对应接口；首页保留主机 DNS 配置指引。
- 接入查询、测速结果与运行事件使用服务端分页，默认每页 10 条，可选 20／50／100 条；筛选在分页前执行。浏览旧页时固定查询快照，新增记录不使当前页跳动；显式刷新返回最新第一页。
- 查询记录最多保留 7 天／10,000 条，测速结果最多 30 天／5,000 条，运行事件最多 30 天／500 条，任一上限到达即清理。条数限制在写入时执行；时间清理在启动时及每小时独立执行，不依赖测速成功。数据库复用已释放页面并定期检查点，清理不改变当前配置和生效策略。
- 展示当前节点、持续下载速度、结果时间、策略生效版本、切换原因与后台任务状态。
- 每日汇总按 UTC 日期和域名保存成功速度平均值／峰值、测速与健康失败次数、读取字节及启用／切换次数，保留 90 天／最多 10,000 行；明细清理后汇总保留。
- 自动选优为默认状态，手动测速、固定节点和暂停选优为辅助操作。
- 明确区分服务端探测速度与主机实际下载速度；单靠 DNS 无法观测下载流量、游戏进度或即时带宽占用。
- 接入验证依据真实收到的查询及应答；经过路由器转发时，设备身份可能只能归到路由器，不推断不存在的设备明细。

## 验收标准

| 层级 | 必须提供的证据 |
| --- | --- |
| 软件 | 无人工点击即可完成候选探测、选择、发布和失效回退；首次查询不等测速；缓存与策略更新不冲突 |
| DNS 协议 | UDP／TCP、A／AAAA、CNAME、NXDOMAIN／NODATA、EDNS 截断与 TCP 重试、改写标志及目标 AAAA NODATA 验证 |
| 故障恢复 | 停止管理容器、损坏策略输入、探测超时、数据库不可写、节点失效、规则订阅失败时解析行为符合规格 |
| Docker | 两种目标架构分别构建，容器启动、重建、数据恢复及端口绑定有记录 |
| 服务主机 | 在明确记录的品牌／型号／系统／网络模式下验证主机 IPv4 查询可达、源地址和重启恢复 |
| 真实主机 | 三平台分别对同一内容做多轮默认 DNS／选优 DNS 对比，记录时段、下载完成时间、平均速度与失败次数 |

软件测试、镜像构建、服务主机部署、主机实测分别报告；不使用某一层通过代替其他层验收。

## 源码发布

GitHub 仓库包含当前源码、依赖锁文件、通用 Docker 部署模板、需求与验证说明，以及第三方许可文本。本地密钥、数据库、查询记录、服务主机实际部署信息、构建缓存和工具不进入仓库。首次发布后核对远端提交与本地一致。

- GitHub Actions 在 main 推送、版本标签和手动触发时，先验证代码，再向 GHCR 发布同时包含 linux/amd64 与 linux/arm64 的镜像；PR 仅验证，不发布。
- main 使用 latest 与完整提交号标签，vX.Y.Z 使用版本及次版本标签；发布记录包含镜像摘要。单独使用默认 Compose 时拉取预构建镜像，Docker 按 manifest 自动选择架构；README 快速部署采用独立 Compose 覆盖文件构建源码。两种方式更新均保留密钥和数据卷，源码、已发布镜像与设备部署状态分别核对。
- 已有服务主机切换 GHCR 时保留原项目名、密钥、配置、历史与有效 IPv4；镜像先准备好再重建。核对实际镜像与数据卷挂载，并验证管理健康、策略同步及 UDP／TCP 应答。直连缓慢时可以导入从 GHCR 获取的同一架构镜像，明确记录传输方式和来源摘要。
- 服务主机后续升级应能直接通过网络拉取 GHCR 发布内容，不依赖电脑导入。可使用验证过的 GHCR 缓存入口，镜像摘要须与上游一致；同时测试服务主机未缓存层的下载与本项目完整拉取，升级保留原配置及数据。维护说明提供固定摘要、更新与回退入口，区分原站与缓存路径。
