# 下载代理

下载代理部署在运行 controller 的设备上，随服务启动，独立监听 TCP 8082，不提供启停开关。它适用于支持手动设置 HTTP 代理的游戏主机；可部署于支持 Docker 的服务主机。

## 接入

1. 按 [部署说明](deployment.md) 配置固定局域网 `SERVER_IP`，发布 TCP 8082。已有部署使用旧 Compose 文件时需补上端口发布。
2. 在首页参数卡的“代理模式”中查看服务器地址、端口和账号密码要求；设置中可按实际网络收窄“允许访问的局域网网段”。
3. 在右侧“配置方式”卡片选择“代理模式”与主机平台，查看设置步骤；Tab 支持方向键和 Home／End。“代理模式”“DNS模式”在左侧同一张参数卡中始终同时显示，代理模式显示当前下载速度。
4. PlayStation 在当前网络的高级／自定义设置中使用代理；Switch 在当前网络的“更改设置 → 代理设置”中启用。填写服务器 IP 和端口 `8082`，无需账号密码或证书，DNS 可保留原配置。
5. 保存、测试网络，再重新开始下载。状态 API 的活动请求／隧道和累计下行流量能确认是否有流量经过代理，但不能识别具体游戏或下载进度。

本版不给 Xbox 提供手动代理设置指引，Xbox 继续使用 DNS 优选。只改 DNS 不会使流量经过代理。主机不同系统或应用是否实际使用代理，需要真实下载验证。

停止 controller 或升级前，先将主机代理改为“不使用”并测试网络；DNS 接入的主机还应恢复自动 DNS 或切换可用服务。进程退出会关闭连接，主机不会因此自动切回直连。旧配置与备份中的 `proxy_enabled` 字段在加载时移除，旧值为 false 也不再关闭代理；新配置不包含该字段。

## 从连接记录补充节点

侧栏“连接记录”显示经过代理的请求：来源 IP、方法、完整 HTTP URL 或 HTTPS 的 CONNECT 域名与端口。记录在请求到达后保存，不等待长下载结束，也不代表下载已成功。Docker／路由器 NAT 可能合并来源，不能据此声称识别了唯一设备。

HTTP GET／HEAD 可打开“添加节点”并预填地址，选择平台后保存。已有域名显示“补充节点”，更新其唯一测速 URL，同时保留平台、候选 IP、启停和内容检查字段。完全相同的 URL 标记为已收录。HTTPS 只能点击“补充下载地址”后人工填写真实下载路径；不猜测根路径。表单继续使用三平台下载域名和内容校验规则，源站可用性由后续实际探测判断。

记录最多保留 7 天／10,000 条，重启保留，不包含认证头、Cookie 或正文。完整 URL 可能包含临时授权参数，数据库与配置中相关 URL 应按私有数据管理，不随源码提交。记录分页与错误处理见 [管理 API](api.md)。

## 转发与选优

HTTP 请求只转发到 80，HTTPS 通过 CONNECT 连接 443。客户端继续与原始域名协商 TLS 并校验证书，服务不解密 HTTPS，也不会安装或签发证书。Range、状态码及响应内容保持，不替换下载地址。

建立源站连接时，精确命中已启用规则且优选未过期就使用当前 IP；暂停自动选优时只有有效固定节点继续适用。没有有效优选，或优选的 TCP 连接失败时，使用配置的上游 DNS 寻找可连接公网 IPv4；其他域名也正常转发。已经建立的连接（包括 HTTP 复用连接）不随策略变化迁移。连接建立后发生 TLS 或内容传输错误时交给客户端重试，不拼接内容或重放已发送的请求。

只接收允许网段与环回来源，目标为公网 IPv4；域名解析后的连接仍校验 IP，不允许借代理访问内网或环回。并发最多 64 个请求／隧道。代理凭据与逐跳头不转发至 HTTP 源站；CONNECT 后的加密内容原样转发。服务不继承环境 HTTP 代理。

状态 API 的代理数据来自本次 controller 进程：`active_transfers` 是正在处理的 HTTP 请求和 CONNECT 隧道，`downloaded_bytes` 是从源站读取的累计字节，含 HTTP／TLS 协议开销。空闲的 CONNECT 长连接也可能显示为活动隧道；累计值不是游戏文件大小。流量不保存到数据库，重启归零；现有测速历史与每日汇总仍只统计后台探测，不混入代理流量。

首页“当前下载速度”约每秒采样 `/api/v1/proxy/traffic`，以累计下行字节增量除以服务端运行时间增量计算，按十进制 MB/s 显示（1 MB = 1,000,000 字节）。它是全部主机经过代理的下行流量合计，包含协议开销；DNS 直连、绕过代理的流量及游戏进度不可见。首次读取或进程重启显示“正在采样…”，没有流量时显示 0.00 MB/s，读取失败显示“暂不可用”；恢复后重新采样，不保留旧速度。只在首页打开时轮询，离开首页即停止。

首版无透明接管、下载缓存、多节点拼接、上游代理、Xbox com／cn 改写或 UDP 转发。转发设备的网络与 CPU 可能限制速度；服务端探测结果不能证明主机已经提速。

## 验证

软件集成测试使用本地 HTTP、TLS、TCP 与 SQLite 夹具，覆盖 Range／HEAD、头部处理、真实证书验证、节点失效回退、来源和目标限制、缓冲隧道、启动即可转发、退出清理、旧关闭状态迁移及备份。运行 `go test ./...`；UI 使用 [浏览器检查脚本](../scripts/browser-check.cjs)。

真实设备用相同主机、网络、游戏内容和相近时段，交替直连／代理至少三轮，记录实际字节、完成时间、失败和重试，另外补测休眠唤醒与停机恢复。记录模板见 [现场验收](field-validation-template.md)，实际通过范围见 [验证记录](validation.md)。

## 设计依据

- [PlayStation 官方连接设置](https://www.playstation.com/en-us/support/connectivity/internet-connect-playstation/)直接列出 PS5 高级网络与 PS4 自定义网络的代理配置。
- [Nintendo 官方网络设置](https://en-americas-support.nintendo.com/app/answers/detail/a_id/22316/)直接列出 Switch 的代理服务器和端口设置。
- [HTTP CONNECT 标准](https://www.rfc-editor.org/rfc/rfc9110.html#name-connect)定义成功后进行双向隧道传输。采用 CONNECT 保留端到端 TLS 是本项目的实现选择。

以上来源证明配置入口及协议含义，不证明平台所有下载均遵循代理设置，更不构成提速证据。
