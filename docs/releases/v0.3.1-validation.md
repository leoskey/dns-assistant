## 复现

1. 核对上述标签、主线发布和官网工作流均成功，并确认 v0.3.1 标签指向本报告记录的发布源码。文档后续更新可以使 main 前进，不据此判断发布二进制的 revision。
2. 使用空 Docker 凭据目录读取 `ghcr.io/leoskey/dns-assistant:0.3.1` 的 manifest，检查 Linux amd64／arm64 条目。按各平台 digest 匿名拉取，在对应平台或模拟器上以 `--network none` 分别运行 `version` 与 `config`；通过 `docker image inspect` 检查 OCI 的 `org.opencontainers.image.version`。CLI、OCI 版本与源码 revision 须同时匹配。
3. 从公开 Release 匿名下载安装 EXE、便携 ZIP 和 SHA256SUMS；使用 `sha256sum --check SHA256SUMS`，或 PowerShell `Get-FileHash -Algorithm SHA256` 对比清单及本报告。将 ZIP 解压到临时目录，运行其中的 `dns-assistant.exe version` 和 `config`；检查安装 EXE 的产品版本。
4. 获取官网实际 HTML，核对页脚、更新记录、文档链接和两个下载链接均指向 v0.3.1。对实际链接跟随重定向，确认最终 HTTP 200，并核对已下载附件的版本和哈希。
5. 需要重复安装／卸载验证时，在无既有安装的隔离 Windows 环境运行仓库的 `scripts/test-windows-package.ps1`。临时 HTML、下载包及执行输出保存在忽略目录，检查结束后清理。
